Support integration and trip planning raise the same product question: which decisions can the system make, and which still belong to a person?

01 / AUTONOMY

Expand scope by risk.

Document retrieval can run within approved access. A refund changes business state: action gates must check authority, conditions, and execution status. Model confidence cannot authorize it. Irreversible actions need a named approver.

Support architecture
02 / EVALS & COORDINATION

Make collaboration earn its cost.

Parallel travel research helps only when the final itinerary stays consistent. Start with a single planner; add specialists for independent research. Task-level evals compare constraints, recovery, cost, and latency. Permission violations remain a separate release blocker.

Trip planning architecture
03 / MEMORY

Remember less. Keep it current.

Trip state, personal preferences, and company policy have different lifetimes. Retain preferences with permission; keep sources and versions with evidence. Corrections, deletions, and access changes must invalidate old context. Evals should replay these changes across sessions.
